## Typography

IBM Plex Sans 400/500/600, IBM Plex Mono for logs and numbers. H1 32 px/1.25, H2 22 px, KPI 36 px tabular, body 16 px, table 14–16 px depending on screen size, metadata 14 px. No 96 px hero delaying data access.

## Grid, Rhythm, and Responsiveness

Sidebar 220 px, main area minmax(0,1fr), max-width does not constrain the dashboard like a landing page. Header controls in 1 row when wide enough; prioritize alerts over charts. Tablet sidebar collapsed with accessible labels; mobile agenda/list replaces compressed tables.

## Surfaces and Materials

Radius 6 px, border 1 px, no shadows on every panel. Use surface 2 to separate levels; alerts must have icon/text, not color alone. Distinct separators without bordering every single cell.

## Components and States

### KPI

Calculated from valid datasets according to timeframe, with clear data scope labels. No sparklines without an accompanying data series.

### Table Toolbar

Search, status filtering, timefilter, and reset; filters have labels, result counts update. No filters hidden inside nameless icons.

### Run Detail

Step timeline, sample inputs, errors, and remediation guidance. Retry is simulated only, creating a new record linked via parentId; retain the old error record.

### Report Export

CSV based on the currently viewed filter, headers with units, standard escaping; fields starting with =, +, -, @ must be handled safely for spreadsheet opening. Do not export secrets.

## Motion and Reduced Motion Options

Status updates 150 ms, no fake count-up on KPIs. Loading only when there is an actual async task, skeletons do not loop infinitely. Reduced-motion does not animate row reordering.

## Things to Avoid

No randomized KPIs, retry buttons executing real workflows, 10 decorative charts, confusing icon-only controls, unfilterable image tables, or fake success states.

## Pre-Deployment Verification

Measure contrast for actual text/surface pairs and real states; do not rely on isolated hex values to declare compliance. Verify complete Vietnamese diacritics and fallback fonts. Content layout, dataset, cover, and specific scenarios follow immediately after this brief in the standalone prompt.

## 4. Specification for Each Content Area and Task

### 1. Overview

**Layout and Behavior:** One title, timeframe, and 3 KPIs calculated from the dataset: total runs / successful / needs attention.

**Content and Output:** No randomized live numbers, Sample Data label displayed next to the timeframe.

### 2. Needs Attention

**Layout and Behavior:** Critical errors above the table: missing email / destination unreachable / invalid data.

**Content and Output:** Each error includes local fix guidance, not vague "Failed".

### 3. Run History

**Layout and Behavior:** Table of 10 records with workflow, time, status, duration; search/filter/sort.

**Content and Output:** Selecting a row opens run-detail, no irrelevant decorative charts.

### 4. Run Details

**Layout and Behavior:** Timeline of steps, sample inputs, and logs; actions: Edit sample data / Simulated rerun.

**Content and Output:** Do not execute real n8n, do not retry sending external messages.

### 5. Reports and Reset

**Layout and Behavior:** Export CSV of the filtered dataset with clear headers, or reset session.

**Content and Output:** Do not call reports Excel if only exporting CSV; no passwords/credentials.

## 5. Data and Interaction States

KPIs are calculated from the entire dataset based on the time filter; clearly state if the table filter uses a different scope. Rerun creates a new run with parentId, without deleting the old error. Filters with no results must have a clear filters button; stable sorting.

Clearly distinguish mock/preset data from real actions: demo functions in the template do not send messages, create orders, book appointments, or trigger external workflows. If a client version later connects to real services, that is a separate integration requiring proper permissions and error handling.

## 6. Responsive and Reading Order

At 768 px sidebar is collapsed; at 390 px items needing attention sit at the top, table converts to a list with details, charts include text summaries. Do not hide errors just to keep the layout clean.

Check additionally at 320 px and 1280×720 to catch clipped text/panel bottoms. DOM order must follow what the user needs to do, not just rearranged with CSS causing broken Tab navigation. Long tables/logs scroll internally within labeled regions.

## 7. Motion and Feedback

State changes 150 ms, data updates do not count-up jitter continuously. Reduced-motion does not affect data.

Do not let motion slow down operations or conceal errors. Save paused state in the session when looping; reduced-motion must preserve all information and content order.
