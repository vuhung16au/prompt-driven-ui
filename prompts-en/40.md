## Typography

IBM Plex Sans 400/500/600, IBM Plex Mono for logs and numbers. H1 32 px/1.25, H2 22 px, KPI 36 px tabular, body 16 px, table 14–16 px depending on screen size, metadata 14 px. No 96 px hero slowing down data access.

## Grid, rhythm, and responsive

Sidebar 220 px, main area minmax(0,1fr), max-width not constraining dashboard like a landing page. Header controls in 1 row when wide enough; prioritize alerts over charts. Tablet sidebar collapsed with access labels; mobile agenda/list replacing squeezed tables.

## Surfaces and materials

Radius 6 px, border 1 px, no shadows on every panel. Use surface 2 to differentiate levels; alerts have icon/text, not just color. Clear separators without bordering every single cell.

## Components and states

### KPI

Calculated from a valid dataset within the timeframe, clear data scope labels. No sparklines without an accompanying data series.

### Table toolbar

Search, status filter, time filter, and reset; filters have labels, updated result count. No hidden filters inside unnamed icons.

### Run detail

Step timeline, sample inputs, errors, and remediation steps. Retry is simulated only, creating a new record linked via parentId; keep the old failed record.

### Report export

CSV based on currently viewed filters, headers with units, standard escaping; fields starting with =, +, -, @ must be handled safely when spreadsheet software opens the file. Do not export secrets.

## Motion and reduced-motion plan

Status updates at 150 ms, no fake count-up on KPIs. Loading only when there is an actual async task, skeleton does not loop infinitely. Reduced-motion does not animate row reordering.

## Things to avoid

Prohibited: random KPIs, retry buttons executing real workflows, 10 decorative charts, confusing icon-only controls, image-based tables that cannot be filtered, or fake success states.

## Value validation before deployment

Measure contrast between text/surface pairs and actual states; do not rely on isolated hex values to declare compliance. Check full Vietnamese diacritics and fallback fonts. The content layout, dataset, cover, and specific scenarios follow immediately after this brief in the standalone prompt.

## 4. Specifications for each content area and task

### 1. Overview

**Layout and behavior:** A title, timeframe, and 3 KPIs calculated from the dataset: total runs / succeeded / needs attention.

### 2. Needs Attention

**Content and output:** Each error has local remediation guidance, not a vague "Failed".

### 3. Run History

**Layout and behavior:** Table of 10 records with workflow, time, status, duration; search/filter/sort.

**Content and output:** Selecting a row opens run-detail, no unrelated decorative charts.

### 4. Run Details

**Layout and behavior:** Step timeline, sample inputs, and logs; actions: Edit Sample Data / Simulate Rerun.

**Content and output:** No real n8n execution, no retry sending external messages.

### 5. Report and Reset

**Layout and behavior:** Export CSV of the filtered dataset with clear headers, or reset session.

**Content and output:** Report must not be called Excel if only exporting CSV; no passwords/credentials.

## 5. Data and interactive states

KPIs are calculated from the entire dataset according to the time filter; must state clearly if table filters use a different scope. Reruns create a new run with parentId, without deleting the old error. Empty filter results must include a clear-filter button; stable sorting.

Clearly distinguish pre-built data from real actions: test features in the template do not send messages, create orders, book appointments, or execute external workflows. If a client version later connects to real services, that is a separate integration requiring proper permissions and error handling.

## 6. Responsive and reading order

At 768 px sidebar collapses; at 390 px action items go to the top, tables turn into lists with details, charts include text summaries. Do not hide errors just to keep layout clean.

Also test at 320 px and 1280×720 to detect clipped text or panel bottoms. DOM order must follow what users need to do, rather than just rearranging visually with CSS and causing Tab navigation to jump erratically. Long tables/logs scroll internally within labeled containers.

## 7. Motion and feedback

State transitions at 150 ms, data updates do not count up jitteringly. Reduced-motion does not affect data.

Do not let motion slow down operations or obscure errors. Save pause state in the session when loops exist; reduced-motion must retain all information and content order.
