Design principles — apply when building pages.

General Rules

Clear Layout
Group related items together. An aligned grid keeps complex pages looking simple.
- Use consistent spacing throughout; do not give every block its own style.
- Items serving the same purpose stand next to each other.
- Visitors should instantly recognize what is content and what is an action.
Lay out on an even grid, group related items closely, maintain unified spacing.

The Important Must Stand Out
One primary task per page. Large text, bold weight, strong color — so eyes land on the right spot.
- Headings, subheadings, and body text must clearly differ.
- Do not make every line the same size or weight.
- A clean page is better than a crammed page.
Visual hierarchy: very large headings, medium body text, smaller supporting text. One primary task per page.

Similar Things Look Similar
Buttons with the same action share the same shape. Visitors do not have to relearn every page.
- Choose one type system, one color palette, and stick to them.
- Same function, same interaction.
- Fewer styles look more refined.
A single type and color system across the entire page. Buttons with the same action must have the same shape and placement.

Readable Text
Body text large enough, lines not too long, Vietnamese accents never clipped.
- At most two or three fonts.
- Body text at least 16px, airy line spacing.
- Roughly 40–75 characters per line, do not stretch across wide screens.
Body text at least 16px, comfortable line-height, 40–75 characters per line. Uppercase labels need 1.4 line-height to avoid clipping Vietnamese accents.

Clicks Must Be Seen
When visitors click, they must know the system registered it. If waiting, state that it is waiting.
- Buttons have hover and active/pressed states.
- Lengthy operations show in-progress copy.
- Visuals serve the task, avoid decoration for its own sake.
Every button has distinct hover and active states. Pending tasks must have status indicators. Do not decorate without serving a task.

Always Provide a Way Out
Confirm before deleting or paying. Always provide a back or cancel button.
- Place cancel / back right where the action is taking place.
- Ask once for actions that cause data loss.
- Preventing mistakes before they happen is better than fixing them later.
Every step has cancel or back. Deletions must ask for confirmation. Never leave visitors stranded.

Accessible to Everyone
Sufficient text contrast. Fully keyboard usable. Mobile friendly to tap.
- Clear contrast between text and background, at least 4.5:1.
- Tab key navigates through all interactive elements.
- Touch targets on mobile must be at least 44px tall.
Text/background contrast reaches 4.5:1. Keyboard navigates all buttons. Mobile touch targets at least 44px tall.

Fits Both Desktop and Mobile
Collapse columns when narrow. No horizontal scrolling. Primary actions remain tappable.
- Fluid grid, do not lock to a fixed width.
- Text scales with the screen, never overflowing.
- Important actions stay within thumb's reach.
Under 640px: single column, no horizontal scroll, buttons span nearly full screen, text never gets cut off.

Reveal Gradually, Do Not Dump Everything
Break long tasks into steps. By default, show only what is needed right away.
- Divide long tasks into steps.
- Indicate which step the user is on.
- Hide what is not yet needed.
Long tasks split into steps with step indicators. By default, only show what is required for the next action.

The User's Task Comes First
Drop anything that does not help them finish the job. Less is easier to use.
- Stay focused strictly on what needs to be done.
- Remove unnecessary burdens.
- A page that finishes the task beats a page with many buttons.
Keep only what helps visitors finish their task. Remove decoration and buttons that do not lead to the next step.

When Fine-Tuning Each Part

Start From the Task, Not the Frame
Ask what the visitor is here to do on this page, then arrange the copy.
- Write the task first, arrange visuals later.
- Save details for last.
- Do not decorate before the purpose is clear.
- Give the page a personality, then limit choices.
Define the one task visitors must complete on this page. Arrange text to serve that task. Fewer choices, one clear personality.

Not Everything Is Equally Important
Tone down secondary areas so primary ones stand out naturally. No gray text on colored backgrounds.
- Big does not always mean prominent — weight and contrast make the difference.
- Drop labels if the text itself says enough.
- Balance text weight against white space.
Lower the weight of secondary areas to make the core elements stand out. Do not use gray text on colored backgrounds. Use labels only when text cannot stand on its own.

Leave White Space First, Then Tighten
Do not fill the entire screen. Use one spacing scale consistently.
- Start spacious, then tighten.
- One set of intervals: 8–12–16–24–40.
- Ambiguous spacing between two blocks is a flaw.
Spacious first. One spacing scale used throughout. Never leave ambiguous gaps between blocks.

Type Has Scale and Alignment
Align to the text baseline, do not center-align everything. Match line height to font size.
- Pick 4–5 font sizes and lock them in.
- Comfortable reading line length, do not stretch across full width.
- Not every link needs a different color.
Lock in a typographic scale. Align to text baselines, do not center blocks. Links in body copy do not necessarily need color changes.

Few Colors, Full Shades
One accent color. Slightly warm gray, not dead gray. Never rely on color alone to report errors.
- Pick a color, then pre-generate shade levels.
- Grays slightly tinted toward the primary color, avoid sterile gray.
- Errors must have text, not just color.
One accent color, a few pre-set shades. Slightly warm grays. Error states have descriptive text, not merely color changes.

Depth From a Single Light Direction
Shadows in one unified direction. Flat design still has layers — subtle overlapping is enough.
- One imaginary light source.
- Shadows express elevation, not decoration.
- Overlap blocks to create depth, do not border every box.
Directional lighting from one side. Soft shadows indicate layers. Minimal borders, use overlapping blocks when elevation separation is needed.

Images Must Support Text Overlays
Sharp images. Text over images must always remain readable. User-uploaded images must have fallback backgrounds.
- Sharp imagery that serves the purpose.
- Text over images must have a backing fill or text shadow sufficient for readability.
- Empty image containers must have a fallback background color to prevent broken layouts.
Sharp images, text over images must be legible. Image slots always have fallback backgrounds when images are missing.

Final Touches
Empty states should also communicate clearly. Reduce borders. Backgrounds with intent.
- Style browser default buttons.
- Zero-data states must include explanatory text.
- Fewer boxes, more space.
Do not leave buttons in browser-default styles. Provide empty states. Fewer borders, more white space.
